# Charkle Windows Engineering Guardrails

These directory-scoped rules apply whenever working under `windows/` (in addition to root `AGENTS.md` §1–§2 and `.trellis/spec/windows/fluent2-design-system.md`).

## Windows Native UI, Win32/OLE & Local Engine Invariants (Tauri + Win32 + React)

- **Frameless DWM / Mica Alt Classic-Frame Suppression (`windowing.rs`)**:
  - When keeping `WS_CAPTION | WS_THICKFRAME` for native Aero Snap alongside `DwmExtendFrameIntoClientArea(-1)` (Mica Alt), always enforce `DWMWA_NCRENDERING_POLICY = DWMNCRP_ENABLED` and `SetWindowThemeAttribute(WTA_NONCLIENT, WTNCA_NODRAWCAPTION | WTNCA_NODRAWICON | WTNCA_NOSYSMENU | WTNCA_NOMIRRORHELP)` before any `SWP_FRAMECHANGED`, strip `WS_SYSMENU` once, suppress `WM_NCPAINT` / `WM_NCUAHDRAWCAPTION` (`0x00AE`) / `WM_NCUAHDRAWFRAME` (`0x00AF`), forward `WM_NCACTIVATE` with `lParam = -1`, and clear the parent HWND GDI surface to pure transparent black (`WM_ERASEBKGND` `BLACK_BRUSH` + `PatBlt(..., BLACKNESS)` after `WM_NCACTIVATE`, `WM_SIZE`, `WM_WINDOWPOSCHANGED`, `WM_SYSCOMMAND`, `WM_SETTEXT`, and `WM_SETICON`) so legacy Aero Basic blue frames never bleed through in windowed or restored states.
- **Win32 OLE DropTarget Process Boundary, Drop Catcher Overlay & Shelf Stability (`shelf_win.rs`, `desktop.rs`, `clipboard.rs`, `lib.rs`)**:
  - **Never** call `RevokeDragDrop` or `RegisterDragDrop` on cross-process WebView2 child HWNDs (`msedgewebview2.exe`, e.g., `Chrome_RenderWidgetHostHWND` / `Intermediate D3D Window` / `Chrome_WidgetWin_1`) — that dereferences foreign-process COM pointers and crashes with `0xC0000005`. Instead, keep own-thread `is_own_thread_hwnd` filtering and route external shelf drops through the pure own-thread layered Win32 `CharkleShelfDropCatcher` popup (`WS_POPUP | WS_EX_TOPMOST | WS_EX_TOOLWINDOW | WS_EX_LAYERED`, `LWA_ALPHA = 1`, `WM_MOUSEACTIVATE => MA_NOACTIVATE`, no `WS_EX_NOACTIVATE`), shown only while an external button press approaches the expanded capsule and hidden synchronously inside `IDropTarget::Drop`.
  - Negotiate `IDropTarget` effects via `select_drop_effect` (intersecting incoming `*pdweffect`: `COPY` > `MOVE` > `LINK`), wrap all Win32 `extern "system"` procs and COM callbacks in `std::panic::catch_unwind`, guard shelf HWND ops with `IsWindow`, serialize shelf creation via `SHELF_BUILD_LOCK`, never re-register drop targets inside `set_shelf_hit_rect`, never double-emit `shelf:state`, and keep top-edge hover open debounced with a cooldown.
  - Keep the WebView2 UI thread unblocked: parse clipboard image previews via zero-encode DIB/PNG header inspection (`read_current_clipboard_preview`) instead of full RGBA/PNG encoding, and run `charkle-media://` disk and SQLite lookups inside `tokio::task::spawn_blocking`.
  - Route OS file/folder drops and clipboard file pastes through `LiveCharkleEngine::ingest_local_paths` so dropped directories mirror their nested folder hierarchy in the library (reusing matching sibling folders, sanitizing reserved names, creating empty folders cleanly, and skipping single broken files without rolling back valid siblings).
- **Outbound OLE Drag-Out & `Alt+Tab` Handoff (`PointerDragContext.tsx`, `drag_out.rs`, `native.rs`)**:
  - Acquire pointer capture on `documentElement` as soon as an asset drag begins so fast pointer exits across window edges still deliver coordinates. Hand off active asset drags immediately to Win32 OLE `startOutboundDrag` (`DoDragDrop`) on viewport exit, `Alt`/`Meta` keydown, or `window.blur` (never blindly cancel an active asset drag on `blur`).
  - Inside `drag_out.rs`, only call `SetForegroundWindow(hwnd)` when starting from the shelf window or when our window is already foreground — never steal focus back from the Windows `Alt+Tab` / `Win+Tab` Task Switcher. Skip decoding fallback original files `> 8 MiB` for drag previews so `DoDragDrop` initiates within a few milliseconds.
- **Fluent 2 Anchors, Centered Segmented Tabs, Acrylic Surfaces & Gallery Perf (`Menu.tsx`, `Popover.tsx`, `SegmentedControl.tsx`, `AssetCard.tsx`)**:
  - Hover-only row triggers (such as FolderTree `...` and Smart Folder actions) collapse to `0×0` `DOMRect` when `:hover` drops, causing Floating UI / Base UI popups to jump to `(0, 0)`. Always keep the trigger mounted/visible while `open` is true and wrap imperative `HTMLElement` anchors in `useResilientElementAnchor` (retaining the last non-zero `DOMRect`).
  - Full-width / grid `SegmentedControl` tracks must distribute tabs evenly and center labels (`flex-1 justify-center`); floating utility bars beneath the top bar (`TopFilterCapsule`, `InboxTriageBar`) must share the top bar's Acrylic translucent material tokens rather than opaque fills; high-cardinality gallery cards (`AssetCard`) must remain `React.memo`-wrapped with primitive store selectors (never subscribing each card to the entire `selectedAssetIds` collection).
- **Strictly Local Visual Fingerprints & Honest Similarity / Smart Triage (`visual_fingerprint.rs`, `library_db.rs`, `engine.rs`, `visual_grounding.rs`)**:
  - Never write Windows local visual descriptors into the synced `asset_vectors.feature_print` column (reserved for cross-platform Apple Vision payloads); cache them in the strictly local `local_visual_descriptors` table.
  - Never grant unconditional `media_kind` or `folder_id` free points in `similar_assets`, and never assign flat fallback scores that tie unmatched folders and blindly pick `folders[0]` in Smart Triage. Require calibrated multi-signal evidence above threshold and abstain honestly (`[]` for similar items; `None` / `"留在收件箱"` with per-row manual override in Inbox Smart Triage).
